## 1. 方法

1. **解析(精确)值**:`native/enum.c`(C + OpenMP)对 5 条轴带的**全部停位组合**穷举(A 基础 33^5≈3.9e7、FS 36^5≈6.0e7、B 34^5≈4.5e7),得到 (线赢总额, 特殊符号数) 的精确分布。A 的 Free Spins 用 (剩余次数, 已授予总数, 阶梯下标) 的动态规划求期望(含重触发、60 次上限、阶梯重置);B 的 H&S 用 (K, R) 马尔可夫链求期望(含 Jackpot 币与满屏奖励)。解析值**不含**最高赢取上限截断。代码:`scripts/analyticA.ts`、`scripts/analyticB.ts`,汇总 `scripts/analyticReport.ts`。
2. **校准**:A 轴带用模拟退火(`scripts/calibrateA.ts`,先 BASE 后 FS,每次评估都是精确枚举);B 基础轴带同法(`calibrateB.ts`),B 的币值权重 / p(K) / q 用 `tuneB.ts` 在固定轴带上搜索,目标函数含"购买 RTP = 正常 RTP"项。
3. **蒙特卡洛**:走真实引擎 `step()/playRound()` 路径(不是解析模型的重实现),投注 100,分 8 个独立进程(seed `final-<game>-<mode>-<i>`),每进程按批输出。RTP 的标准误用"批 RTP 的样本标准差/√批数"估计(200 批;批大小:A 正常 1,000,000 局、B 正常 2,000,000 局、A 购买 100,000 次、B 购买 200,000 次),并用"每局赢额方差"的解析 SE 交叉检验,两者一致(见下表)。复现:`bash scripts/finalSim.sh && bash scripts/finalMerge.sh`。

规则文档的建议价(A 75x、B 60x)是"初始建议值",并标注 [数学可调]、"由数学校准";校准结果落在 48x 和 85x,方向相反。这个价格需要产品/合规确认(尤其 A 的 48x 仅为基础旋转平均成本的 48 倍,而 FS 触发率 1/153)。

## 7. 局限与未覆盖项(如实说明)

1. **上限(5000x / 10000x)在真实配置的模拟中从未触发**(A 最大 845x,B 最大 2187x),所以上限对 RTP 的实际压缩为 0,解析值(不含上限)与模拟一致正是这个原因。上限逻辑由用注入配置构造的确定性测试覆盖(`test/engineA.test.ts`、`test/engineB.test.ts`)。
